# LangGPT 结构化提示词方法论（本技能的提示词底座）

LangGPT 是开源的结构化提示词框架（GitHub: EmbraceAGI/LangGPT，社区站 langgpt.ai）。核心思想是「模块化搭建 AI 专家」：不写一大段请求，而是用一组固定模块，给大模型拼出一位专家——他是谁、擅长什么、守什么规矩、按什么顺序干活、用什么格式交卷。

## 八核心模块（每条提示词必须齐全，标题不得省略，无内容写「无」）

| 模块 | 作用 | 写法要求 |
|---|---|---|
| Role | AI 扮演谁 | 一句话：职业 + 段位 + 突出特点，如「你是有 10 年经验的区域经营知识库管理专家」；与规格卡角色定位一致 |
| Profile | 角色简介 | 2-4 条要点：擅长什么、服务对象、工作边界；记录作者、版本、语言，便于升级 |
| Goal | 要达成什么 | 1-3 条，每条以动词开头、可验证；与规格卡该场景的验收标准一一对应 |
| Skills | 需要什么能力 | 3-6 条，动宾短语，尽量具体 |
| Rules | 执行中守什么 | 分「必须」「禁止」两组；重申宪章红线并引用宪章编号；每条必须可判断 |
| Workflow | 按什么顺序干 | 编号步骤；第 1 步永远是输入检查；需要人拍板的步骤显式标注「⏸ 人工确认」 |
| OutputFormat | 用什么格式交卷 | 输出结构骨架：标题层级、字段、长度区间、风格引用（如「遵循宪章风格 G1」）；有固定模板的直接贴出 |
| Initialization | 开场第一句说什么 | 固定 AI 首句：声明角色、索要第一步输入；不泄露内部规则细节 |

### 可选进阶模块（按需添加，不强制）
- **Commands**：定义口令，如「当用户输入 /诊断 时执行 xxx」。适合反复使用的场景提示词。
- **Examples**：给 1-2 组「输入 → 期望输出」示例（few-shot）。稳定风格与格式最有效的手段。

## 单条提示词模板

```
# <编号> <场景名>

## Role
<一句话>

## Profile
- 作者：【作者】· 版本：1.0 · 语言：中文
- <要点 1：擅长什么>
- <要点 2：服务对象>
- <要点 3：工作边界>

## Goal
<唯一目标，可验证>

## Skills
1. <能力 1>
2. <能力 2>

## Rules
必须：
- <规则 1>（引用宪章编号，如「宪章 R2」）
禁止：
- <红线 1>

## Workflow
1. 输入检查：<声明需要什么输入、什么格式拒收或需预处理>
2. <处理>
3. ⏸ 人工确认：<给用户看什么、等用户答什么>（无人工确认点的场景删除本行）
4. <按 OutputFormat 产出>

## OutputFormat
<结构骨架：标题层级、字段、长度区间、风格引用>

## Initialization
作为 <Role>，我会遵守以上规则。<第一句开场白>。请先提供：<第一步需要的输入>。
```

## 质量自查清单（每条提示词生成后逐项过）

- [ ] 八核心模块标题齐全
- [ ] Role 是具体专家，不是万能「助手」
- [ ] Goal 每条以动词开头、可验证，与场景验收标准对应
- [ ] Rules「禁止」组至少覆盖宪章全部红线，且引用宪章编号
- [ ] Workflow 第 1 步是输入检查；人工确认点有 ⏸ 标注
- [ ] OutputFormat 有明确形态契约（结构/长度/风格引用）
- [ ] Initialization 固定了开场，不泄露内部规则细节
- [ ] 占位符与「占位符清单」一致，无硬编码的组织/角色专属内容
