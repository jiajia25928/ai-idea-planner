# 场景文档标准（蓝图产出必须对齐此标准）

蓝图产出的每份场景文档共用一套三段结构：**方法**（解决什么、给谁用、怎么用）+ **可执行主体**（可复制的提示词与操作）+ **后续跟进**（拿到结果怎么看、什么时候重跑）。按场景性质分四类。

## A 型：诊断评估类提示词

适用：知识库健康度检查、AI 对话质量评估等「给现状打分」的场景。

固定结构（按序）：
1. **用途一句话**：这份提示词诊断什么、给谁用、拿到什么报告。
2. **使用说明**：编号步骤、一步一个动作（如：打开日常在用的 AI → 复制提示词块 → 一键发出并告知等待时长 → 拿到报告 → 按周期重跑）。
3. **提示词复制块**，内部依次含：
   - 角色设定：不是温和的助理，而是「懂评估、会核验证据、敢直说」的复盘教练；明确要求直接表达，不用含糊的缓和词。
   - 评估框架：把评估对象拆成 3–5 个递进阶段（如知识库可分「能找到 → 能使用 → 能思考」三阶段；对话系统可按使用深度分层），用表格写清每阶段的定位与解决什么。
   - 评分维度与权重：百分制，每维写满分、高分区特征、低分区特征。维度与权重按使用者自己仓库的侧重设计；示例六维：结构完整度 20 + 内容沉淀 20 + 材料转化率 15 + 知识提炼 25 + 行动复盘 10 + 互相关联 10。
   - 抽样与判定规则：抽样数量写明（如「每类最多抽 5 份，不足 5 份全看」）；阈值写明（如「某类内容占比 ≥15% 才算高频」）；设**强制降级条款**（核心维度低于某分时，整体阶段强制下调，优先于基础规则）。
   - 诊断步骤：分区扫描 → 抽样打开 → 新鲜度检查 → 数据统计；强调一切统计必须实际数出来，不允许估算。
   - 输出格式契约：固定输出顺序（各维得分 + 理由 + 短板 + 建议 → 总分 → 阶段判定 → 关键证据 → 三大短板 → 三层优化建议 → 单选下一步 → 重跑预期）。
   - 收尾点评：让 AI 用一句话（不超过 30 字）直接点评当前状态。
   - 输出前自检清单：AI 输出前逐项自查（总分是否等于各维之和、证据是否具体到文件、字数是否达标、口吻是否合规等），自检全部通过才正式输出。
4. **拿到报告之后**：按优先级给「先看这几件事」（阶段判定、有无触发强制降级、核心维度、短板 + 证据、单选下一步）。
5. **重跑建议**：如 3 周后重跑，看阶段是否上升、核心维度分数是否上涨。

关键设计点：每个得分都要有具体证据（具体文件路径，不接受笼统概括）；建议分层（今天就能做 / 7 天内 / 1 个月）；结尾给单选「下一步」而不是一堆建议。

## B 型：搭建教程

适用：从 0 到 1 搭起一套系统（知识库、提示词库、自动化流程等）。

固定结构：
1. **流程总览**：先把全部步骤编号亮出来，让用户知道总工作量；写明执行原则（一步一个动作、不贪多；先搭最小可用版本，再用真实材料测试手感）。
2. **每一步 = 一个动作**，每步四件套：
   - 为什么做（人话，一两句）
   - 怎么做（完整可复制提示词块；提示词里写明「这一轮只做 N 件事」+ 一串「不要做什么」）
   - 完成后能看到什么（可验证的结果）
   - 新手注意（如：第一批资料建议 10–20 份、优先文本可读的格式、读不完整就补一句「继续读取」）
3. **试跑步**：用一个简单真实任务验收（如新开对话直接问一句任务，不加特殊口令）。
4. **全面检查步**：只输出问题清单和建议，不直接改动内容。
5. **规则沉淀**：把确认过的协作规则写进仓库的全局规则文件（你的 AI 工具支持的规则文件，如 AGENTS.md、CLAUDE.md 或自定义系统提示词），让 AI 每次对话都遵守。

关键设计点：一步不叠加多个动作；凡 AI 写入仓库，必须先预览、用户确认后再写入；不预设真实项目名，先用一个虚构的示例项目走通流程，等真实材料进来再替换。

## C 型：场景卡（每种 AI 协作模式一张卡）

每个模式/场景一张卡，固定字段：
- **适用场景**（什么时候用，列条目）
- **一句启动语**（最短开场白，可直接复制）
- **主提示词**（完整复制块，五要素：模式声明、任务主体、已给输入、期望产出、边界与自检）
- **精简版**（课堂/培训用的一段式简化版）
- **常见误区**（3-5 条，典型用错方式）
- **切换信号**（出现什么信号就换另一个模式）

另附**跨场景链路**说明（同一任务如何按顺序组合多个模式）和一张**模式切换提示词**。

关键设计点：每张卡写清人和 AI 各自的责任；要求 AI「先复述理解，无关键缺口再执行，完成后逐项自检」；给「切换信号」，让用户不在一种模式里卡死。

## D 型：大量资料导入教程（B 型变体，用于大量资料场景）

在 B 型之上必须加四件事：
1. **劝退一次性倾倒**：先说明为什么不建议一次导入过多（AI 容易抓错重点、读取不充分、待判断内容越积越多）。
2. **导入文件夹分类表**：每类说明放什么（通俗解释）、典型内容、什么不要放（如「我与我的工作 = 让 AI 先知道我是谁；常放职责说明、述职材料；不要放全员人事档案」）。
3. **命名规范**：默认不改名（别让人替 AI 做整理）；仅三种情况补最小信息（名字看不出内容、同名太多、缺日期对象），格式自定，原则是「看文件名能知道日期、对象、来源」。
4. **分批顺序 + 每批专属提示词**：按依赖关系分批（先「我是谁」→ 背景环境 → 判断依据 → 运转机制 → 工作对象 → 具体证据 → AI 对话记录 → 外部参考）；每批处理完，AI 必须主动发出「本批需要你确认的点」；规则沉淀进全局规则文件。

## 生成蓝图时如何选用

- 诊断/评估/打分类场景 → A 型
- 日常高频使用场景 → C 型
- 搭建/从零启动/迁移流程 → B 型
- 涉及大量资料入库的场景 → B 型 + D 型
- 任何场景文档里的「提示词复制块」，内核都是一条 LangGPT 八模块提示词（或其精简变体）——标准是外壳，LangGPT 是内核。
