# 场景采集清单与场景规格卡

## 用法
阶段 2：把下方「场景采集清单」**一次性整份**发给用户填写（可复制填空），不要逐条追问。用户返回后，阶段 3 把答案整理成「场景规格卡」交用户确认。
清单允许部分留空：留空项在规格卡中标注「待定」，并给出一个明确标注为建议值的默认选项，由用户确认。

## 场景采集清单（原样发给用户）

```
【AI 能力蓝图 · 场景采集清单】
请逐项填写，不确定的可以留空，我整理时会给出建议值。

零、能力类型（必填）
0. 你最想做的事是（可多选，请标注哪个是主要的）：
   □ 知识库仓库型——有很多资料，想让 AI 整理好、随问随答
   □ 提示词库型——想要一套不同场合用的提示词
   □ 功能技能型——想把一项能力封装起来随时调用
   □ 应用型——想要看得见的页面/小工具（如数据看板）
   □ 自动化型——想让 AI 定期自动做一件事（如自媒体发布）
   □ 对话应用型——想和 AI 进行一类特定对话（如述职提问）
   补充：你对这类工具的熟悉程度？（完全没接触过 / 会用常见聊天 AI / 会用本地笔记软件 + AI 类工具）

一、使用角色（必填）
1. 这套能力给谁用？（角色名称，如：区域经营负责人 / 培训负责人 / 销售团队负责人）
2. 这个角色的日常核心工作是什么？（2-3 句话）
3. 这个角色不擅长/不想亲自做的事是什么？（蓝图要替他解决的部分）

二、应用场景（必填，可写多条）
4. 列出所有要用这套能力完成的场景，每条写清楚三件事：
   场景名 | 输入是什么（什么文件/什么问题/什么素材） | 期望输出是什么（什么格式/给谁看）
   示例：会议内容入库 | 输入：会议逐字稿、汇报PPT等文件 | 输出：结构化笔记并归类到指定文件夹

三、载体与环境（必填）
5. 在哪里使用？（如：本地笔记软件 + AI / 某AI对话产品 / 公司AI平台 / AI应用搭建平台，写产品名）
6. 有没有文件格式限制？（该载体读不了哪些格式，如音频、视频、PDF）
7. （应用型/自动化型必答）数据从哪来？涉及哪些账号或权限？

四、风格与红线（重要）
8. 输出内容的固定风格要求？（如：先结论后论据 / 必须带数据 / 口语化 / 直接不客气）
9. 绝对不能做的事？（如：不许编造数据 / 不许引用库外信息 / 敏感信息不外传 / 公开发布必须先审）

五、复用与定制（用于让其他组织直接复制使用）
10. 哪些内容换个组织/角色就不适用了？（如组织名、行业术语、审批流程）
    ——不确定的留空，我会自动识别并用占位符标注
```

## 场景规格卡模板（阶段 3 产出，交用户确认）

```
# 场景规格卡：<蓝图名称>

## 能力类型
- 主类型：<…>；组合类型：<…>（组合方式：<…>）
- 用户技术水平：<…>（决定教程详略）

## 角色定位
- 角色：<名称>
- 核心工作：<…>
- 要解决的问题：<…>

## 全局宪章（草案）
- 统一风格：<…>
- 全局红线：<…>
- 命名规范：<…>

## 场景清单（每场景一条，编号 S1、S2…）
### S1 <场景名>
- 输入：<…>
- 输出：<格式 / 长度 / 受众>
- 触发方式：<用户怎么用>
- 人工确认点：<有/无，在哪一步>
- 验收标准：<输出满足什么算合格>

## 占位符清单（复用时需替换）
- 【角色名称】/【组织名称】/【风格描述】/ …

## 待定项
- <留空项>：建议值 <…>（请确认）
```

## 整理规则
- 用户描述的场景 ≥ 8 条时，先归类合并再出规格卡（同类场景合成一条，备注变体）。
- 每条场景必须有可判断的验收标准；用户没说的，按「输出格式正确 + 覆盖输入要点 + 符合宪章」三条补齐并标注为建议值。
- 涉及自动化型/应用型的，规格卡必须包含数据源与权限字段；涉及公开发布的场景必须包含人工审核门。
- 规格卡确认后才进入阶段 4；用户修改规格卡即更新，不口头记忆变更。
