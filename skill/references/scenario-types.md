# 六大能力类型：交付物清单、搭建流程与注意事项

SKILL.md 阶段 1 定型后读对应章节。场景常是多类型组合：按主要目标定型，蓝图里说明组合方式（如「知识库仓库型打底 + 对话应用型做入口」）。

## 1. 知识库仓库型
**定义**：让 AI 在一个固定位置管理、使用一堆资料。载体不预设：可以是本地笔记软件 + AI，也可以是自带知识库能力的 AI 产品。
**判断信号**：「有很多资料」「想让 AI 整理且随问随答」「沉淀成知识库」「课程/培训资料仓库」。
**典型例子**：区域经营负责人知识库、内部培训团队课程培训体系仓库。
**载体建议（写进蓝图）**：根据用户的技术水平与资料形态给 1–2 个组合建议并说明理由——如「本地笔记软件 + AI 插件」（适合资料想留在本地、目录自己管的人，常见的如 Obsidian 类工具）、「自带知识库的 AI 对话产品」（适合不想装任何东西、开箱即用的人）。用户已有在用的工具时优先沿用，不强行推荐新工具。
**交付物清单（蓝图骨架）**：
1. 仓库目录结构（每个文件夹用表格说明：文件夹 / 用途（人话）/ 放什么 / 不放什么）
2. 全局协作规则文件（你的 AI 工具支持的规则文件）：交互分类、先预览后写入、确认队列、判断边界——分工原则是「AI 负责整理与建议，人负责判断与拍板」
3. 资料导入流程（D 型：分批 + 每批专属提示词 + 每批待确认点）
4. 日常场景提示词：问答、报告/课程稿生成等（C 型卡）
5. 知识库健康度诊断提示词（A 型）
6. 搭建教程（B 型：建目录骨架 → 定协作规则 → 导入第一批资料（建议 10–20 份）→ 预览确认式整理 → 真实任务试跑 → 全面检查）
**注意事项（必须写进蓝图）**：
- 不一次性倾倒资料，分批整理、分批确认
- 资料改名按最小信息原则；默认不改名，别让人替 AI 干活
- AI 写入仓库必须先预览、人确认后写入
- 区分四类信息：事实、用户原话、AI 推断、候选结论；AI 的分析不能直接升级成结论
- 全面检查只输出问题清单与建议，不直接改动内容

## 2. 提示词库型
**定义**：一套覆盖某角色多个场景的可复用提示词，配宪章、README、定制指南。
**判断信号**：「想要一套提示词」「不同场合用不同提示词」「给别人也能复制着用」。
**交付物清单**：宪章 → 场景规格卡 → 逐场景的场景文档（范式外壳 + LangGPT 提示词）→ README → 定制指南（占位符替换表）→ 验收清单。
**搭建流程**：即本技能六阶段主流程。
**注意事项**：一切占位符化；宪章编号全库唯一且被提示词引用；新增场景先过验收再入库；一个场景只对应一条提示词。

## 3. 功能技能型
**定义**：把一项能力封装成可复用的技能（skill），装进 AI 助手，一句话触发。
**判断信号**：「想把这个做成技能」「让别人也能用」「说一句话就触发」。
**交付物清单**：
1. 技能定位说明：只解决什么问题、不解决什么、触发语（用户会说什么话）
2. 技能主文档：触发条件、主流程、硬性规则（用祈使句写）
3. 参考文档：模板、范例、规范等，按需加载，不塞进主文档
4. 试用验收清单（用 2-3 个真实任务试跑，记录卡点）
**设计理念（做技能的标准范式）**：
- 一个技能只解决一类问题，贪多就拆成多个
- 触发条件写进主文档描述里，用用户自己的话写（用户想用它时会说什么）
- 渐进式披露：元信息常驻约百字、主文档触发时加载、参考文档按需加载
- 主文档控制在 500 行以内；长内容拆到参考文档
**注意事项**：对非技术用户先解释「技能 = 一套提前写好的专家工作方法，AI 听到触发语就加载照做」；技能内容是 Markdown 文本，不神秘、可阅读可修改。

## 4. 应用型（页面/工具/看板）
**定义**：想要一个看得见摸得着的页面或小工具。
**判断信号**：「想要一个看板」「一个页面」「一个小工具」。
**典型例子**：业务数据看板、计算器、展示页。
**交付物清单**：
1. 一页纸需求说明：给谁看 / 看什么数据 / 数据从哪来 / 能做什么操作 / 谁来维护更新
2. 数据准备说明：数据以什么格式存在、谁维护、有无权限限制
3. 分段搭建提示词：在 AI 应用搭建平台上按「整体布局 → 逐页细化 → 接入数据 → 美化」分段生成，每段一个动作，不要一段提示词要求全部
4. 验收要点清单：数据对不对、非技术人员能否打开使用、手机上能否看
**注意事项**：
- 数据源和权限通常是最大的坑：先回答「数据从哪来」，再谈界面
- 先用假数据/样例数据跑通，再接真实数据
- 界面分轮次改进：先骨架对，再调细节
- 涉及真实业务数据的，把数据边界红线（谁能看、不外传）写进需求说明

## 5. 自动化型（定期/自动执行）
**定义**：AI 按固定时间或事件自动做一件事。
**判断信号**：「每天自动发」「每周一自动汇总」「不想每次手动」。
**典型例子**：自媒体发布、定期报表、定期提醒。
**交付物清单**：
1. 自动化流程图：触发条件 → AI 做什么（逐步）→ 哪几步有人工审核门 → 结果去哪
2. 每环节的提示词（内容生成、自检、格式转换等各一条，LangGPT 结构）
3. 人工确认点设计：哪些步骤必须人看过才能放行
4. 准备清单：账号、平台权限、素材库、凭据存放位置
5. 风控与合规注意：平台发布规则、内容审核边界、发布频率限制
**注意事项**：
- 涉及公开发布的自动化必须留人工审核门，禁止全自动直发
- 先手动跑通几遍验证稳定，再开自动化
- 留「暂停/回退」方法，并用大白话写清楚
- 平台规则常变，把「复查平台规则」放进定期流程

## 6. 对话应用型
**定义**：和 AI 进行一类特定对话（提问、教练、模拟、述职）。
**判断信号**：「想让 AI 提问我」「模拟某某」「预演述职」。
**典型例子**：业务述职直接提问应用、教练式犀利提问、模拟答辩。
**交付物清单**：
1. 角色设定卡：AI 扮演谁（身份、风格、口头禅、专业边界、绝对不做什么）
2. 对话流程设计：开场（固定第一句）→ 追问规则（一次只问一个、往深处钻不铺开发问、跑题怎么拉回）→ 收尾（输出报告/评分/行动清单）
3. 提问/评估框架：述职类给问题清单或出题规则 + 评分维度；教练类给提问原则（如「单点钻深、不铺开发问」「直来直去，看到什么问题就直接指出」）
4. 完整 LangGPT 提示词（Initialization 固定开场；Rules 写明兜底话术：无法判断时说什么、不编造）
5. 试用调优指南：试跑后怎么记录问题（AI 哪里问得差/跑题）、对应改哪个模块
**注意事项**：
- 防跑题必须写进 Rules：用户跑题时用固定话术拉回
- 评分维度必须可判断，不靠 AI 自由发挥
- 对话记录可沉淀回知识库（与知识库仓库型组合）

## 分类速查（用户描述含糊时，把这段发给用户自选）
「下面哪句话最像你想做的事？可以多选，请标注哪个是主要的。」
1. 我有很多资料，想让 AI 整理好并随问随答 → 知识库仓库型
2. 我想要一套不同场合用的提示词 → 提示词库型
3. 我想把一项能力封装起来，随时调用 → 功能技能型
4. 我想要一个看得见的页面或小工具 → 应用型
5. 我想让 AI 定期自动帮我做一件事 → 自动化型
6. 我想和 AI 进行一类特定对话 → 对话应用型
